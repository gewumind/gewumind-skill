## 定时任务实战坑

本文记录实际项目开发中踩到并定位的坑，按「现象 → 根因 → 处理」组织。

---

## 1. 任务配了 cron 却从不执行（最隐蔽）

**现象**：`.ms` 里 `cron` 写对了，但到点没有任何日志，数据库也没变化。

**根因**：`TaskInfo` 中 `enabled` 是 Java 原生 `boolean`，缺省值是 **false**。
`TaskMagicDynamicRegistry` 注册了 CronTask，但每次触发都会先判断
`if (entity.isEnabled())`，为 false 直接跳过 —— **完全静默**。

**处理**：任务 meta 必须显式写 `"enabled": true`。

```json
{
  "name": "每日清理",
  "cron": "0 0 3 * * ?",
  "cronExpression": "0 0 3 * * ?",
  "enabled": true,
  "description": "每天 03:00 清理过期数据"
}
```

> 判断任务是否真的在跑：日志里搜 `[magic-task-` 线程名。注册成功但未启用时**没有任何输出**。

## 2. `log.info()` 报「对象为空」

**现象**：
```
MagicScriptException: 对象为空 at Row:32~32
log.info("每日打卡统计 ...")
```

**根因**：`log` 是 magic-script 的**模块**，不是自动注入的变量。

**处理**：`import log` 后再使用（见 `00-overview.md` 坑 1）。

---

## 3. 没有手动触发入口，只能改 cron 验证

`/task/execute` 在嵌入部署下 404（见 `00-overview.md` 坑 2）。

**处理：临时高频 cron 验证法**

```bash
# 1. 把任务 cron 临时改成每 20 秒（源码目录与后端 data 目录两份都要改）
#    "cron": "*/20 * * * * ?"   "cronExpression": "*/20 * * * * ?"

# 2. 造夹具数据（务必带明显前缀，跑完删干净）
#    例：清理类任务造「待清理 / 应保留」两类样本；统计类任务造一条目标日期的数据

# 3. 重启后端
bash <项目>/scripts/restart9001.sh   # 或项目自己的重启脚本

# 4. 等 20~30 秒，观察日志与数据变化
grep "任务日志里的关键字" <后端日志目录>/*.log

# 5. 清理夹具 → 改回正式 cron → 再重启
```

**要点**：
- 夹具要**可辨认**（如 `e2e_` 前缀），便于 `DELETE ... WHERE id LIKE 'e2e_%'` 一次性清干净；
- 验证完必须把 cron 改回正式值，否则任务会一直高频跑；
- 统计类任务验证「幂等」要**连跑多轮**，确认不会重复插入。

## 4. `.ms` 文件被写坏导致启动期解析异常

**现象**：
```
MagicScriptException: literal cannot be used alone at Row:1~1
```
或任务注册了但 `script` 为 null。

**根因**：手写 meta 时分隔符不对。`.ms` 结构是：

```
{JSON meta}
================================
{script}
```

**分隔符必须带首尾 `\r\n`**，且 `meta` 与 `====` 之间、分隔符与脚本之间都要换行。
拼接时若写成 `json + "====" + body`（缺换行），整个文件被当作脚本解析。

**处理**：改完 `.ms` 用二进制校验（见铁律 10），并保持 `src/magic-api/task/` 与
`backend/data/magic-api/task/` 两份**完全一致**（`diff -r` 必须无输出）。

## 5. 清理类任务的通用设计要点

写「清理/归档」任务时，下面几条能避免事故：

| 要点 | 说明 |
|---|---|
| 只清**孤儿**数据 | 删除前必须排除「仍被业务引用」的行，否则历史附件/记录会凭空消失 |
| 物理删除 vs 逻辑删除 | 同一事务内**先删磁盘文件、成功后再标记删除**；文件删失败就跳过，下次重试 |
| 数量上限 | 单次 `limit` 500，避免任务跑超时 |
| 保留期可配 | 走 `sys_configure` 配置项（如 `<模块>.clean.keepDays`），不要写死 |
| 防目录穿越 | 拼路径后判断不含 `..` 再删除 |
| 日志文件特殊 | 只删**归档**（`*.log.*` / `*.gz`），正在写入的 `*.log` 不动（活动句柄删了空间也不释放） |

**自查**：任务跑完后，随机抽 1~2 条本应保留的数据，确认没被误删。

- [ ] `groupId` 能在本目录链上找到对应 `group.json`
- [ ] `src` 与 `backend/data` 两份 task 完全一致（`diff -r` 无输出）
- [ ] 清理类任务有「引用保护 + 数量上限 + 保留期配置」
- [ ] 改完 cron / enabled 后**重启过**后端
